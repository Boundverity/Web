Evidence-based deployment decisions for AI agents

Boundverity turns an organisation’s own access policy and workflow rules into independently checked tests and a decision-grade report, so a CISO can approve, condition or reject an agent with the evidence in front of them.

Open-source tooling for CISOs, service owners and assurance providers.

The problem

Agents are being given real permissions. The approval decision has no good evidence behind it.

Public bodies and regulated organisations are starting to let AI agents read tickets and documents, update records and grant access. The person asked to approve each deployment cannot easily answer one question: will this agent, with these permissions, in our workflow, stay within our policy and recover safely when something fails?

Model benchmarks, generic red-team results and vendor assurances do not answer it, and manual assessment neither scales nor keeps pace with change. Organisations end up delaying useful deployments, or approving them on assurance that would not survive scrutiny after an incident.

Our approach

For a specific agent configuration, a clear recommendation and the evidence behind it.

The report recommends approve, approve with conditions, reject or insufficient evidence. It names the controls, owners and monitoring required, and states exactly which changes invalidate it. The accountable owner signs the decision. The tool never authorises deployment itself.

Tests from your policy

Intended authority, effective permissions and the task scope of each request are kept separate, so contradictions and gaps are exposed. Unresolved cases return “insufficient evidence”, never a pass.

Independent, auditable verdicts

An independent deterministic checker, built separately from the test generator and making no AI model calls, produces every result.

Evidence that expires on change

Each report is bound to a configuration manifest. When the model, prompt, tools, permissions or approval rules change, the assurance lapses and reassessment is triggered.

How it works

An evaluation and evidence pipeline that sits around the agent and its tools.

It tests whether the configuration and controls an organisation has chosen are adequate for a stated workflow. Tests cover security risks such as prompt injection, data disclosure, unauthorised provisioning and data egress, and resilience risks such as partial failure, retries, duplicates, safe recovery and human handover.

Policy model and validator
An open YAML schema that detects contradictions, omissions and untrusted claims.
Test generator
Deterministic templates for legitimate, boundary, attack and failure cases, including stateful approval and recovery sequences.
Independent checker
A separate implementation that evaluates action sequences, disclosures and final system state.
Tool gateway
A default-deny path for every tool call, with identity and request-bound approval checks.
Inspect adapter
Runs agents and approval policies inside the UK AI Security Institute’s open-source Inspect framework.
Evidence service
Append-only, signed records of attempted, authorised and executed actions.
Decision report and change monitor
Produces the recommendation and detects configuration drift that triggers reassessment.

Open source

Core outputs are released under Apache 2.0.

Any UK organisation can adopt the method without a paid service. Boundverity plans to offer managed reassessment on top of the open toolkit: hosted and continuously monitored reassessment, trained review of flagged results, maintained connectors for directory and ticketing systems, and signed assessment reports for audit and procurement.
